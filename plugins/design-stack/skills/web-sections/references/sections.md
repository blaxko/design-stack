# Page sections

Categories from unsection.com (5,000+ real section screenshots). Live examples: `https://www.unsection.com/category/<slug>`. Jiro (jiro.build) covers the same set as copy-paste prompts; see SKILL.md.

| Section | Unsection slug | Job | Strong patterns | Must have |
|---|---|---|---|---|
| **Hero** | `hero-section-design` | State what it is, for whom, and the next step, in 5 seconds | Split (text + product visual); centered statement + product screenshot below; full-bleed visual with overlay text; interactive demo as the visual | Headline ≤ 10 words in plain language, subline with the specific benefit, 1 primary + 1 secondary action, a real product visual or live element, no autoplay sound |
| **Logos / social proof** | `logo-section-design` | Borrow credibility | Single muted row; slow marquee; "Trusted by teams at" + 5–8 marks | Only real customers/partners/integrations you're allowed to show, monochrome, consistent height |
| **Features** | `feature-section-design` | Explain the key capabilities | Alternating text/visual rows; tabbed features with one visual; bento (see bento.md); numbered steps for "how it works" | Benefit-led titles, each backed by a visual of the actual product, max 3–6 features per section |
| **Stats / metrics** | (within feature) | Prove scale | 3–4 big numbers with short labels | Real, sourced, dated numbers only; light font weight for big numerals often looks more premium |
| **Testimonials** | `testimonial-section-design` | Proof from people | One big quote; 2–3 quote cards; wall/masonry for many; video testimonials | Real name, role, company, photo; specific outcomes; never invented |
| **Pricing** | `pricing-section-design` | Help choose a plan | 2–4 tiers with one highlighted; monthly/annual toggle; comparison table below | What's included per tier, who it's for, the CTA names the plan, FAQ about billing nearby |
| **FAQ** | `faq-section-design` | Remove last doubts | Accordion in one or two columns; FAQ beside a contact prompt | 5–10 real questions (pricing, security, setup, cancellation), answers ≤ 3 sentences, first one open |
| **CTA** | `cta-section-design` | Convert at the end | See cta.md | One action, risk-reducer line |
| **Team** | `team-section-design` | Humanise | Grid of photos with name/role; founders with short bios | Consistent photo treatment, real people |
| **Contact** | `contact-section-design` | Get in touch | Form + alternative channels; map for physical businesses | Minimal fields, response-time expectation, success state |
| **Blog** | `blog-section-design` | Show freshness/expertise | Featured post + list; 3-card row | Dates, reading time, real posts only |
| **Portfolio** | `portfolio-section-design` | Show work | Large case-study cards; filterable grid | Outcome per project, fast-loading images |
| **Navbar / Footer** | `navbar-design`, `footer-section-design` | | See navbar.md, footer.md | |

## Landing page default order (adapt, don't follow blindly)
Navbar → Hero → Logos (if real) → Problem/metaphor → Features or bento → How it works (3 steps) → Proof (stats/testimonials) → Pricing (if public) → FAQ → Final CTA → Footer.

For developer tools add a code/SDK section after features; for web3 add a trust section (non-custodial, audited/verified contracts with explorer links, network) before the final CTA.
